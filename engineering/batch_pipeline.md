# Batch pipeline

1. Verify available fields and define economic mechanisms.
2. Freeze candidate expressions, settings and provenance.
3. Apply static checks and select a balanced batch.
4. Run platform simulations through a rate-aware queue and record outcomes.
5. Capture IS checks, annual statistics and aligned daily PnL where available.
6. Compare candidates with the current ACTIVE set and with one another.
7. Record failures, unresolved requests and research decisions for the next batch.

An ambiguous request is reconciled against account records before retrying. A platform check can return pending or an empty response; the record retains that state until a result is available. Manual submission is a separate action.
